# 04. Roadmap tail in-context

## What to build

The same move for roadmaps: a roadmap pick keeps the grilling session, the
Response returns to it, and that session stages the work into `docs/roadmaps/`
— stage briefs written by the context that settled them. The roadmap follower
watches the existing session (roadmap landed off the base commit, plus quiet)
and carries the Conversation on to its pull request as it does today.

The ladder for a roadmap Conversation becomes Grilling → Wrapping: Implementing
never happens on the planning Conversation, because Implementing means the
Implementation Profile is driving and on a roadmap the building belongs to the
Stage Conversations. The rung is skipped, not idled in.

The grilling skill's closing section gains the roadmap branch (read the staging
skill and follow it), and the staging skill is reframed for both entries the
way breaking-down was in task 03 — mid-session, and fresh for a retried tail.
Any staging approval rounds are ordinary Sets from the same session.

## Acceptance criteria

- [ ] A roadmap pick leaves the grilling session running; that session writes
      and commits the roadmap; no fresh staging session is launched.
- [ ] The roadmap Conversation moves Grilling → Wrapping when the session is
      seen out, and its Stages start the ordinary unattended way.
- [ ] The staging skill works from both entries.
