# 04. Install from the Desktop page

## What to build

The way back once Don't ask again is ticked: the same Install, reached from the
Desktop section of the settings page over the preload bridge.

**Two more channels on the bridge**, declared where the nine are and said again
on the viewer's side, with the literals pinned by the two suites that keep the
sides in step. One answers *where this run is from*: whether the app runs from
outside Applications and, where it does, the path it runs from — answered from
the same decision task 01 and 02 built, and *installed* on a checkout run, a
browser and a phone alike. The other is the press, answering once the install
has been declined or has failed, since a success relaunches the app.

**The row** stands in the Desktop section beside Launch on startup and View
Logs, drawn only while the app says it runs from outside Applications: a line
naming where it runs from in `code`, and an **Install** button. Nothing is drawn
in a browser, on a phone, or once installed. The press raises the same native
dialog with the same words and one more sentence when sessions are running on
this device, naming them as stopped and resumed, read the way the Update card
reads them; with none running, the dialog is the launch's own. Install moves and
relaunches as the dialog's Install does, the running sidecar going with the
quit; Skip, the box and a failure behave as at launch, and the row says the
failure under the button as the registration's refusal is said under its box.

The page's conventions hold: a control shows where things stand, so the row
reads the bridge's answer and never assumes a press worked.

## Acceptance criteria

- [ ] No row in a browser, on a phone, on a checkout run, or once the app runs from Applications; the row with the path and the button while it does not.
- [ ] The press raises the dialog; with sessions running it names them as stopped and resumed; Install relaunches the app from Applications; a failure is said under the button.
- [ ] The row is under the web suite with the stubbed bridge beside the section's other cases, both suites pin the new literals, and `web/` and `desktop/` checks are green.
