# 04. Attaching a pack from an Answer

## What to build

ADR-0028's second moment, for packs: the Attach control on every Answer field
and on the set-level comment box offers the installed packs not yet on the
Conversation, beside its MCP servers.

A pick is recorded on the Set the moment it is made — surviving a reload,
showing on another device, removable with ×, struck on a settled Set — as a
new kind of pending addition beside the server one, and applied at Submit in
the transaction that stores the Response. A pack picked and no longer
installed (or disabled) by Submit refuses the Submit, naming it, as an
undeclared server does.

A pack changes what is bound, so it widens the sandbox the way a Companion
does: where a session is waiting on that very Set (not a Deferred Ask), it is
ended and carried on through the harness's resume, primed with the
sandbox-changed note, and the new launch mounts the pack and lists it under
`# Skill packs`. The Answer's `added` entries name the pack and the path it
is mounted at, so the digest, a handoff and a Share can say what came with
the Answer, and the Timeline line says it was added.

## Acceptance criteria

- [ ] A pack added on an Answer carries the waiting session on in a sandbox
      that has it mounted and a prompt that lists it
- [ ] A pack no longer installed or enabled by Submit refuses the Submit,
      naming it
- [ ] A Deferred Ask answered with a pack restarts nothing, and the pack is on
      the Conversation for its next session
