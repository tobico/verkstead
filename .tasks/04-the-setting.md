# 04. The setting

## What to build

How many Conversations may take a place across the server becomes a **server
setting**, four where nobody has said otherwise, and task 01's constant reads it.

`conversations`, under the `at_once` section beside `roadmap_stages` — the one
section about *how much of this machine does Verkstead help itself to*, which is
the question this is a second answer to. Written into the settings file the way
everything else there is, and read **afresh at every start** the way the git
author and the build cache are: an absent key, an absent file and one nothing can
parse all mean four, a whole number below one is read as nobody having said, and
a change reaches the next start without a restart and stops nothing already
running.

On the settings page it is a **second field on the card stage 04 built**, which
was written with room beside its one field for exactly this. The card says both
numbers. The page refuses a number below one here as it refuses one there, and
for the same reason: a server with no places starts nothing, ever, and that is
not a state worth being able to configure.

**And the pane says how many places are taken right now.** A server whose places
are all held by stages waiting on answers starts nothing more until one is
answered, and that has to be visible rather than looking like a stall — so the
number the limit is measured against is drawn beside the limit itself, read off
the same two registers task 01 counts and as of the moment the page asked.

## Acceptance criteria

- [ ] Set to one, Verkstead starts nothing by itself while any Conversation is
      running or being driven, and starts it when that one finishes.
- [ ] A change takes effect at the next start and stops nothing already running;
      a settings file with no key, one nothing can parse, and a number below one
      all mean four.
- [ ] The card says both numbers, and the pane says how many of the server's
      places are taken as it was drawn.
