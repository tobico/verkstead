# 02. The Tinker start

## What to build

**Tinker becomes a Process a human can pick, and Start on one lands Follow-up.**
The two halves are one slice because either without the other is wrong: a row
offered over a press that grills would start the wrong thing, and a start path
nothing can reach is not a start.

**On the composer.** The Process picker offers *Tinker* beside *Develop*, and
the server accepts it — both lists grow a row, the viewer's and the record's.
The per-Process role table already says what Tinker is run under: Implementation
and Review, Review pickable away, the **Agent** control taking the panel shape.
So no Grilling picker is drawn, the panel stacks the two, and the inert Start
says it is waiting on a brief and both roles.

**Readiness follows the Process.** Start on a Tinker waits on the two roles it
uses and never on the grilling one — the same reading that decides the press is
what decides the button, on the Conversation's composer and the compose page
both. There is already a two-role readiness in the server for a Draft holding a
pull request; Tinker asks the same question, so it is the same answer rather
than a second one written beside it.

**The press does the grill start's own sequence.** Fetch, resolve the base, cut
the branch, make the Worktree and every companion's, freeze the Brief and the
Pairings, remember them against the Repo — all of it the same work, refused by
the same names, with the branch name settled the same way. What differs is two
things and only two: the Conversation lands **Follow-up** rather than Grilling,
and the session launched into the Worktree is the follow-up's rather than the
interview's. A Conversation that already has a Worktree is handled exactly as it
is for a grill start.

**The session is the follow-up's session**, under the Implementation Pairing,
on the `following-up` skill. It is primed with the Brief in the *What I want to
follow up on* place — the Brief goes there and nowhere else in the prompt, so
the session reads it once, under the heading that says act on it — with no
handoff and nothing already said. The naming instruction is appended as it is
for every first session, because the branch is still carrying the name Verkstead
invented.

Nothing about the ending changes here: the Nothing-else mark and the Done signal
are task 04's.

## Acceptance criteria

- [ ] A Draft can be set to Tinker from the composer, and its setup row draws the
      Agent panel with Implementation and Review and no Grilling picker.
- [ ] Start on a Tinker is inert while the Brief is empty or either role is
      unanswered, saying it waits on a brief and both roles; a Review picked away
      counts as answered.
- [ ] Pressing a ready Tinker's Start leaves the Conversation in Follow-up with a
      branch, a Worktree and every companion checked out, the Brief and the
      Pairings frozen, and the move on the Timeline.
- [ ] One session is running under the Implementation Pairing on the
      `following-up` skill, its prompt carrying the Brief as what to follow up on
      and the instruction to rename the branch, and no handoff.
