# 03. The app bundle and the dmg

## What to build

A script that turns a built workspace into `Verkstead.app` inside a dmg, run
from the dev shell or a runner the way `tools/build-appimage.sh` is, taking
everything from the working tree and leaving one file at a fixed path it prints
at the end.

Three pieces:

- **The universal binary.** `lipo` over `verkstead-desktop` built for
  `aarch64-apple-darwin` and `x86_64-apple-darwin`, so one app runs on both
  Macs.
- **The bundle.** The `.app` layout with `Info.plist` naming
  `net.tobico.Verkstead` as the bundle identifier, `Verkstead` as the name, the
  workspace version, and the app as a menu-bar agent rather than a windowed
  application — there is no window behind the tray icon and there should be no
  Dock tile.
- **The icon.** An `.icns` generated into `packaging/` by
  `tools/generate-packaging.sh`, which already says this stage adds it and
  already generates the PNG sizes it is built from. That script rewrites
  `packaging/` from nothing on every run and its output is committed, so the
  icns is generated and committed and never hand-drawn. It tops out at 512:
  the one piece of artwork is 545 square, everything is a downscale, and an icon
  scaled up is the one that looks wrong.

Then the dmg around it. Unsigned, per the stage's decision — what a downloader
has to do about Gatekeeper is the docs task's, not this one's.

## Acceptance criteria

- [ ] The script runs on a Mac from a working tree with the viewer built, and
      leaves one dmg at a fixed path
- [ ] The app launches from the mounted dmg, puts its icon in the menu bar and
      serves the viewer — with the viewer really inside it rather than a 503
- [ ] The icns is generated by `tools/generate-packaging.sh` and committed, and
      a second run of that script leaves the tree unchanged
