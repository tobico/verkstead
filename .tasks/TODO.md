# The Agent control

The three role pickers on the composer become one control, **Agent**, whose
shape is the Process's. Where the Process uses several roles it is a trigger
dropping a panel — the way the Repo option beside it does — holding the role
pickers stacked under their labels, and the trigger reads the Implementation
Pairing's reading with ` +1` for each other role picked onto a different
Pairing, or *Not chosen* while a required role is empty. Where the Process uses
one role it is today's flat Pairing dropdown, labelled *Agent*. The setup row
reads Repo, Process, Agent, on the compose page and the saved Draft's composer
both.

Which roles a Process uses is a table in one place the web reads, so a later
stage adds a row rather than a branch. Readiness is unchanged in substance — the
press still waits on every role the Process uses — and what changes is the
words, which name the roles the Process has. The per-Repo Pairing memory and the
platform default are untouched: they are keyed by role, and the panel's pickers
are the same pickers on the same prefill.
