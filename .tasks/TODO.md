# Resuming the harness

A transferred agent keeps its context. Where the harness has a resume of its
own, the session that starts on the receiving device is that resume rather than
a fresh one — run against the log the memory sync carried over, and primed with
a short note saying it now runs on this machine, with the Worktree at its new
path and the new ids of any Question Sets it had open, the wait on them having
gone with the process. Where the log is not where it should be, or there is no
session on the record to resume, Verkstead's own Resume stands as stage 09 left
it, with a Notice saying which.

All four harnesses have a resume line, so what separates them is not whether
they can be resumed but whether Verkstead knows the session id to resume by: it
names Claude's and Grok's at launch, and Codex's and OpenCode's are the
backend's own and have to be written down as the Transcript search finds them.
And each of the three after Claude keys its store by the directory the session
ran in somewhere the memory sync does not rewrite, so each needs its own
relocation.
