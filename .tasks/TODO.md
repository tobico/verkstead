# 04. Grok Build

xAI's `grok` is a backend. A Conversation is grilled and built under a Grok
Build Profile: its session log *named* at launch the way Claude's is,
store-and-nudge asking, screen-signature idling, its JSONL Transcript on the
Timeline, and the form offering the type.

Stages 01 to 03 built the ground and proved it on one backend — the agent type,
the one-home account, the per-type launch line and binary, screen-signature
idle with its byte-quiet long-stop, the Guide tailored per channel, and
store-and-nudge asking. What this stage adds is Grok Build's own: its launch
line, the session id it takes at launch, its idle signature, its updates log
found under the name Verkstead gave it, the renderer for a log written as
streamed session updates, and its usage-limit phrase.

**Two things this stage stands on that are not in the repository.** There is no
`grok` on the machine and no `~/.grok`, and the installer that is meant to put
the binary on the system profile has not. The human's answer was to install it
before this stage is worked, so a task that reaches for the real binary should
find one; if it does not, take the slice as far as the stubs allow and record
the real-thing criterion as waiting rather than quietly softening it. An xAI
account is the second, and the end-to-end proof needs one.
