# 04. Continue what stands

## What to build

The Implementing target, on the half of it that needs no writing: where the
branch already holds a backlog or a roadmap, the modal offers to **carry it on**,
and submitting starts the next step.

The recompute is the one Resume already does for an implementing Conversation —
the backlog's own answer to what is next, asked of the branch exactly as every
other turn of the run asks it — and it is reused rather than forked.

**Offered only where something actually stands**: a backlog with work left in it,
or a roadmap the branch wrote. Where nothing does, continuing is not offered,
and a hand-written instruction is what the target needs instead. That
instruction is the task after this one, so until it lands a steer into
Implementing with nothing to continue is refused by name.

**A continue steer leaves the direction it found.** What says how the work is
being built is the Conversation's own pick, and carrying on with it changes
nothing about that.

The rest of the submit is task 02's, unchanged: force-stop where **Interrupt
current task** was ticked, recreate a Worktree that has gone, clear the stop,
move, record the Steer Event, and launch. The implementation **Pairing** is
shown, prefilled and recorded as the Conversation's.

## Acceptance criteria

- [ ] Continuing is offered only where the branch holds a backlog with work left
      in it or a roadmap.
- [ ] Submitting carries on from the next step exactly as Resume does, with the
      stop written at click cleared first.
- [ ] The direction the Conversation already carries is left as it stands.
- [ ] Steering into Implementing with nothing to continue is refused by name.
