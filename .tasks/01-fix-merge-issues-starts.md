# 01. Fix Merge Issues starts

## What to build

**Fix Merge Issues** becomes a Process a human can pick and press Start on. The
row appears on the Process picker, the **Target** field is drawn for it under
the Branch field the way it is for Review, the one **Agent** dropdown stands
over the Implementation Pairing — the table that says so is already written —
and Start is the take-up stage 05 built, reused whole.

Three facts about a Process are kept in two places each, the server's and the
viewer's, and each is written knowing the other is there: which Processes the
record will accept against which the picker offers, and which take a Target
against which draw the field. Fix Merge Issues joins both halves of both. The
readiness rule gains an arm: one role, judged exactly as an Investigate's one
role is judged, plus a brief and something in the Target field.

The take-up itself refuses any Process but Review today, in one place, and both
composers ask whether the Process is Review before choosing which endpoint the
Start press reaches. All three become the question *is this Process pointed at
work that is already somewhere else* rather than *is this Review*. Nothing
about the take-up's own behaviour changes: the same fetch, the same refusals
each keeping its name and its sentence, the same head at take-up as the base
commit with GitHub's base beside it, recording the pull request as the move —
and over a bare branch the same move made by the take-up itself with one
`submitting` session sent for the pull request nobody opened, against the base
the picker holds.

At the end of this task a Fix Merge Issues Conversation reaches Wrapping and
runs the **ordinary** wrap-up, review and all. Narrowing it is task 02.

## Acceptance criteria

- [ ] *Fix merge issues* is offered on the Process picker, the record accepts
      it on a drafting Conversation, and its Agent control is the dropdown over
      one Implementation picker with no *No review* row anywhere.
- [ ] A Fix draft's Start is inert until it has a brief, a target and one
      Pairing, and its tooltip says exactly those three — *one role*, not both.
- [ ] The Target field is drawn in the Repo panel for a Fix draft, fills from
      the first pull request URL or `#number` in a saved Brief while it is
      empty, and never overwrites what the human typed.
- [ ] Start on a Fix draft naming an open pull request lands Wrapping with that
      pull request recorded, and every take-up refusal — a fork, a diverged
      head, a branch not on origin, one another Conversation holds — keeps the
      name and the sentence it had for a Review.
- [ ] Start on a Fix draft naming a bare branch lands Wrapping with no pull
      request recorded, and `submitting` opens one against the picked base.
