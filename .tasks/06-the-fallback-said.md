# 06. The fallback, said

## What to build

Everything the five tasks before this one let fall through, gathered into one
answer the human can read — and the stage's own demonstration.

**The fallback is not a failure.** Verkstead's Resume is a complete way to take
up a Conversation that has landed, and it is what stage 09 shipped; what makes
it worth saying is that the human can see two outcomes from the same press and
has no way to tell which happened. A resumed agent picks up mid-sentence; a
re-primed one starts the state again from the record. So the arrival's Notice
says which, and where it was the fallback, why.

The reasons are each a real situation rather than an error:

- **The memory switch is off on the Profile**, so nothing of the store
  travelled and there is no log on this device to resume — a session away from
  home starts new exactly as it does at home, and this is that rule reaching
  the arrival.
- **No log where the sync should have left one** — the part came over empty,
  the Worktree's stem came out differently on this device, or the relocation
  could not name a destination.
- **No session on the record to resume** — a Conversation that arrived before
  it had ever run one, or one whose sessions were on a backend that names
  none and whose id was never written down.
- **The Pairing names another harness than the log's** — a Profile changed
  under the Conversation, leaving a log no other backend can read.
- **The resume itself was refused** by the harness, which is the one reason
  known only after the launch.

Each comes out as Verkstead's Resume with the Notice naming it, and the open
Sets locked as they are today, that being the branch where the reader really
has gone.

**And the demonstration is this task's**, and it is the stage's own: a grilling
mid-interview on one device, transferred, carrying on from the same question on
another — across two operating systems, because the Worktree's new path, the
path separators and each harness's own encoding of a working directory are all
in the way of it working and are exactly what one machine's run would not
prove. Read back on both ends: the Timeline, the note the agent was primed
with, and an answer to a Set that was open at the move reaching the session
that is now running.

## Acceptance criteria

- [ ] Each reason the harness resume cannot happen produces Verkstead's Resume
      and a Notice on the arrival naming which reason it was.
- [ ] An arrival that *did* resume the harness says so on the Timeline too, so
      the two outcomes are told apart.
- [ ] A grilling transferred mid-interview between two devices on different
      operating systems carries on from the same question, with the Timeline,
      the note and the Worktree read back on both ends.
- [ ] A Set left open across that move is answered afterwards and its answer
      reaches the resumed session.
